title: "存取方法概述"
---

NexusAPI 支援主流 AI 用戶端及類似 OpenAI 的介面呼叫。 不同工具可能會自動縫合路徑，所以你應該根據使用方式填寫地址。

## 開始前的準備

無論採用哪種方法，以下條件皆為必要條件：

1. 在主控台建立 API 金鑰。
2. 確認 API 金鑰群組包含目標模型。
3. 從模型廣場複製出完整的型號ID。
4. 請求是透過 HTTPS 位址提出的。

## 位址與協定比較

| 場景 | 填寫地址 | 主要協議 | 註釋 |
| --- | --- | --- | --- |
| OpenAI SDK / 通用程式 | `https://nexusapi.link/v1` | 聊天複雜性等等 | 請求路徑由 SDK 或程式串接 |
| Codex CLI | `https://nexusapi.link/v1` | 回應 | 請使用Codex教學中的供應者設定 |
| 克勞德密碼 | `https://nexusapi.link` | 人類訊息 | 設定後不要新增多個位址 `/v1` |
| CC 交換器 | 依照提供者類型填寫 | 這取決於目標工具 | Claude 的地址規則和 Codex 不同 |

上表用於協助選擇存取方式。 完整的介面路徑、參數與反應結構仍為 [API 參考文件](https://nexusapi.apifox.cn/) 作為標準。

## 為什麼地址可能不同

通用的 OpenAI 式請求通常會使用：

```text
https://nexusapi.link/v1
```

有些客戶端要求省略此項 `/v1` 網站地址可能會自動填寫 `/chat/completions`、`/responses`、`/messages` 以及其他途徑。 請參考相應的工具教學以取得準確度。

<Warning>
**避免重複同樣的路**

如果客戶會自動完成， `/v1`，可在人工填充後形成 `/v1/v1/...` 這也導致了404。 遇到 404 時，先確認客戶的實際請求地址。
</Warning>
## 不要將用戶端設定與一般 API 混用

CLI 工具、編輯器外掛及自訂程式可能會使用不同的協定與設定檔。 即使型號名稱相同，你也無法直接將一個工具的整個配置複製到另一個工具中。

判斷方法：

- 設定 Codex CLI：閱讀 Codex 教學並使用相關的回應設定。
- 設定 Claude 程式碼：閱讀使用 Anthropic 環境變數的 Claude Code 教學。
- 寫自己的程式碼：根據 API 參考選擇請求路徑和參數。
- 不確定時：先確認客戶名稱和實際請求路徑。

## 如何確認設定成功

- 客戶端可以正常回傳完整內容。
- 對應的請求會出現在主控台使用紀錄中。
- 日誌中的模型、分組與消耗量均符合預期。

若呼叫失敗，請儲存錯誤文字與請求 ID，然後輸入[自我檢查問題](/zh-TW/faq/self-check)。
