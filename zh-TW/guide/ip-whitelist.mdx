**填入白名單後，只有清單中的 IP 能使用這把 Key；留空則不限制 IP。呼叫仍需要正確的 Key。**

比對以平台辨識到的來源 IP 為準；代理或網路變更可能影響辨識結果，白名單不能取代妥善保管 Key。

適合有固定公網 IP 的電腦或伺服器。經常切換網路或使用動態 IP 時，先確認出口 IP 是否固定，避免儲存後無法呼叫。

## 1. 先確認該填哪個 IP

填**實際呼叫 NexusAPI 的公網出口 IP**，不是 NexusAPI 網站的 IP，也不是電腦的區域網路 IP。

| 在哪裡使用 Key | 應該填什麼 |
| --- | --- |
| 自己電腦上的 Claude Code、Codex 等軟體 | 這台電腦連外時的公網出口 IP |
| 公司伺服器、自建應用或容器 | 伺服器實際對外請求的出口 IP；可向維運確認 |
| 透過代理、VPN 或第三方雲端工具呼叫 | 實際轉送請求的出口 IP；不一定是電腦的 IP，先向服務提供者確認 |

不要填 `192.168.x.x`、`10.x.x.x`、`127.0.0.1`，也不要填網域、網址或連接埠。

**不知道公網 IP？** 在實際執行軟體的電腦或伺服器查詢，保持與軟體相同的網路和代理設定：

Windows：開啟 PowerShell，執行：

```powershell
curl.exe -4 https://api.ipify.org
```

macOS / Linux：開啟終端機，執行：

```bash
curl -4 https://api.ipify.org
```

傳回的數字就是該查詢請求的公網 IPv4。[ipify](https://www.ipify.org/) 是第三方公網 IP 查詢服務，不需要、也不要傳送 API Key。查詢失敗時，向公司維運或網路服務商確認。

如果軟體單獨使用代理、請求從雲端發出，或實際走 IPv6，這個 IPv4 查詢結果可能不是軟體的出口。請先確認實際來源再填寫。

## 2. 開啟白名單並儲存

1. 開啟 [API 金鑰](https://nexusapi.link/keys)，找到軟體正在使用的 Key。
2. 點該列的「編輯」。
3. 展開「進階設定」，找到「IP 白名單（支援 CIDR 表達式）」。
4. 填入實際公網 IP，**每行一個**。
5. 點「儲存變更」。

建立 Key 時也在同一位置填寫。不需要重新複製或更換 Key；修改會影響共用這把 Key 的所有軟體與同事，儲存前先確認。

## 3. 一個或多個 IP 怎麼填

**只允許一個 IP：**

```text
203.0.113.10
```

**允許多個 IP：每個 IP 換一行，不用逗號、分號或空格分隔。**

```text
203.0.113.10
198.51.100.20
```

以上都是示範位址，不能照抄；請替換為自己的實際公網 IP。不要加 `https://`、`:443` 或 `*`。

## 4. CIDR 表達式怎麼設定

### CIDR 是什麼

**CIDR 是用一行表示單個 IP 或整段 IP 的寫法：`IP位址/前綴長度`。** 例如 `203.0.113.0/24`。

斜線後的數字決定範圍大小，**不是連接埠，也不是允許的 IP 數量**。`/24` 不代表允許 24 個 IP。同為 IPv4 或同為 IPv6 時，數字越小，放行範圍越大。

只有一台固定出口的電腦或伺服器，直接填公網 IP 即可，不必改成 CIDR。公司明確提供整個網段時，才照提供的 CIDR 填寫。

### 常見寫法與實際範圍

| 寫法範例 | 實際允許範圍 |
| --- | --- |
| `203.0.113.10` 或 `203.0.113.10/32` | 只允許 `203.0.113.10`，共 1 個 IPv4 位址 |
| `203.0.113.0/28` | 從 `203.0.113.0` 到 `203.0.113.15`，共 16 個 IPv4 位址 |
| `203.0.113.0/24` | 從 `203.0.113.0` 到 `203.0.113.255`，共 256 個 IPv4 位址 |
| `2001:db8::10` 或 `2001:db8::10/128` | 只允許這一個 IPv6 位址 |

這些都是示範位址，不能照抄。不要隨手在自己的 IP 後加 `/24`，這會把單個位址的權限擴大到整個網段。

### 在輸入框中怎麼填

例如，公司確認允許整個網段，另加一台獨立伺服器，就在「IP 白名單」中分兩行填寫：

```text
203.0.113.0/24
198.51.100.20/32
```

替換成維運確認的實際網段與伺服器 IP，再點「儲存變更」。IP 與 CIDR 可以混填，**每行一條，符合任意一條即可通過 IP 檢查**；其他金鑰、模型與額度限制仍然有效。

只有幾個不連續的 IP，逐行填寫即可。不要填 `203.0.113.*`、`203.0.113.10-203.0.113.20` 或單獨的 `/24`，這些不是支援的寫法。不知道如何表示一段位址時，請維運提供準確的 CIDR，不要自行擴大範圍。

IPv4 與 IPv6 可以混填；只填 IPv4 不會同時放行 IPv6。需要查詢 IPv6 時，可在支援 IPv6 的網路使用 `curl -6 https://api6.ipify.org`；Windows 使用 `curl.exe`。查不到不代表軟體一定走 IPv4。

**不要為了消除錯誤填入 `0.0.0.0/0` 或 `::/0`。** 它們分別放行所有 IPv4 或 IPv6，失去限制來源的作用。不確定網段時先問維運。

## 5. 儲存後檢查與排錯

回到原軟體，傳送一次簡短請求。正常回覆表示這次請求通過 IP 檢查，不代表其他來源也已驗證。模型測試按正常呼叫計費。

若錯誤指出 IP 不在允許清單，或 `403` 的原文明確提及 IP 限制，依序檢查：

1. 編輯的是否為軟體實際使用的 Key，是否按了「儲存變更」。
2. 多個 IP 是否分行，有沒有多填網址、連接埠或錯誤字元。
3. 是否切換 Wi-Fi、手機熱點、代理節點或伺服器出口，導致公網 IP 改變。
4. 軟體是否實際走 IPv6，或請求從第三方伺服器發出。

仍失敗時，把軟體名稱、發生時間、Key 名稱與錯誤原文提供給客服，請協助核對該次請求被辨識到的來源 IP。不要傳完整 Key。並非所有 `403` 都是白名單問題，其他情況看[常見錯誤](/zh-TW/faq/common-errors)。

## 6. 修改或關閉限制

回到同一把 Key 的編輯頁：新增位址另起一行，替換位址則修改原來那行，再儲存。

需要關閉時，清空白名單的**全部內容**再儲存。關閉後不再限制來源 IP，但呼叫仍需正確的 Key；公司要求限制來源時，先取得管理員確認，不要自行取消。

白名單不能取代保護 Key。Key 已外洩時，按[金鑰外洩處理](/zh-TW/guide/api-key)立即停用舊 Key，不要只改白名單。
