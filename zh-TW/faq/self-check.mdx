---
title: "自我檢查問題"
---

若通話失敗，請先點擊此頁面完成基本檢查。 大多數配置或偶發問題都能在幾分鐘內判斷。

## 步驟一：儲存網站

在關閉客戶或重新申請前，請先儲存：

- 原文完全錯誤
- 請求識別碼
- 發生時間與時區
- 所用模型
- 用戶端與所用版本
- 例如請求介面 `/v1/responses`

請勿提交完整的 API 金鑰、密碼、私人資料或完整的商業內容。

## 步驟二：確定問題類型

| 現象 | 優先檢查 |
| --- | --- |
| 401 | API Key，`Bearer` 前綴、請求地址 |
| 404 | 檢查基礎網址是否重複或遺失 `/v1` |
| 400 | 模型、介面、參數與會話狀態 |
| 429 | 並行與請求頻率 |
| 500 / 502 / 503 | 等10~30秒再試一次 |
| 504 / 524 | 請求內容、等待時間與服務狀態 |
| 餘額不足 | 控制台餘額、鑰匙數量與分組 |

具體意義請見下方 [API 呼叫常見問題集](/zh-TW/faq/common-errors)。

## 步驟3：進行最低驗證

1. 確認主控台餘額和 API 金鑰是否正常運作。
2. 從模型方格複製模型 ID。
3. 建立一個新會話並發送簡短文字。
4. 只重試一次，並記錄新的請求 ID。
5. 檢查一下主機使用紀錄是否顯示對應的請求。

若新會話成功，問題通常與原始會話狀態或請求內容有關; 如果即使是最小的請求也持續失敗，請提交問題。

## 聯絡客服時提供

請立即提供以下資料：

```text
发生时间（含时区）：
Request ID：
客户端及版本：
模型：
请求接口：
错误原文：
偶发还是持续发生：
是否已用新会话验证：
```

資訊越完整，定位速度越快。 API 金鑰最多可提供最後 6 位元。
