多數設定錯誤或短暫失敗可在幾分鐘內縮小範圍。請先保存現場，再進行一次低頻的最小測試。

## 1. 保存現場

在關閉用戶端或重試前，記下：

- 完整錯誤原文與 Request ID
- 發生時間和時區
- 模型 ID、請求端點、是否串流
- 用戶端／SDK 名稱與版本

不要傳送完整 API Key、密碼、隱私資料或完整業務內容。

## 2. 判斷類型

| 現象 | 優先檢查 |
| --- | --- |
| 401 | API Key、`Bearer` 前綴、請求位址。 |
| 403 | Key 群組、模型限制、IP 白名單、帳戶或上游拒絕。 |
| 404 | Base URL、路徑及 `/v1` 是否重複或缺失。 |
| 400 | 模型、協定、參數或會話狀態。 |
| 429 | 併發與頻率；依 `Retry-After` 等待。 |
| 500／502／503 | 等待 10–30 秒後只重試一次。 |
| 504／524 | 請求大小、等待時間和服務狀態。 |
| `500, not implemented` | 不要重試；檢查是否以 Responses 呼叫 Claude 類模型。 |
| `no available channel` | 模型 ID、Key 群組和當前模型可用性。 |

完整說明請看[常見 API 錯誤](/zh-TW/faq/common-errors)。

## 3. 做一次最小測試

1. 確認控制台餘額和 Key 狀態。
2. 從模型廣場重新複製模型 ID。
3. 新建會話，只送出短文字。
4. 最多重試一次，並記下新的 Request ID。
5. 檢查控制台日誌是否有對應記錄。

若新會話成功，原問題可能與會話狀態或內容有關；若最小請求仍失敗，請提交保存的資料。

## 提交給支援的格式

```text
發生時間（含時區）：
Request ID：
用戶端及版本：
模型：
請求端點：
完整錯誤原文：
偶發還是持續：
是否已用新會話測試：
```

若需要識別 Key，最多提供末六位。
