找到相同報錯，先照下面做。不會處理就把軟體、時間、模型、分組與報錯截圖傳給客服。**遮住完整 Key，不要連續重試。**

## `status_code=500, not implemented`

先不要重試。請客服確認模型是否適用於你的軟體；自行寫程式才需看下方技術說明。

<Accordion title="詳細原因（可略過）">

若錯誤同時包含 `status_code=500` 和 `not implemented`，請先確認所選模型是否支援目前端點使用的協定。例如，`/v1/responses` 需要 `supported_endpoint_types` 包含 `openai-response`；缺少該類型時，這是**協定不相容**，不是等待即可恢復的上游故障。

1. 自建程式請依 `supported_endpoint_types` 選擇介面；包含 `openai` 時使用 Chat Completions：`/v1/chat/completions`。
2. Claude Code 請依[Claude Code 教學](/zh-TW/tools/claude-code)設定，並確認模型支援 `anthropic`。
3. 請先改用相符的端點再測試；等待或換網路都不會修正協定不相容。

需要協助時，請提供已遮蔽的請求範例、模型名稱與 Request ID，勿提供 API Key。

</Accordion>

## 400 Bad Request／參數不相容

先保存重要內容，再開新對話測試一次。仍失敗就傳軟體名稱、模型與截圖給客服。

<Accordion title="詳細原因（可略過）">

400 通常表示請求格式、參數或對話狀態不符合目前端點要求。請依序檢查：

1. 模型 ID 是否從模型廣場準確複製。
2. 端點是否與模型和用戶端相符；請先看[串接方式總覽](/zh-TW/guide/integration-overview)。
3. 是否帶入目前模型不支援的圖片、工具呼叫、推理或對話續接參數。
4. 用戶端或 SDK 是否過舊。
5. 新建對話後，以簡短文字是否仍會出現。

修正可能原因後，請以一條最小請求驗證結果。

</Accordion>

## 401 Unauthorized

重新複製完整 Key，貼上後重啟軟體，確認 Key 已啟用且未到期。不要把 Key 傳給客服。

<Accordion title="詳細原因（可略過）">

常見原因是 API Key 缺失、填寫錯誤、已停用／到期，或鑑權標頭格式錯誤。

```http
Authorization: Bearer YOUR_API_KEY
```

請從控制台重新複製 Key 並確認請求位址。不要把完整 Key 傳給支援；若懷疑洩漏，先停用舊 Key、建立新 Key，再更新程式。

</Accordion>

## 403 Forbidden

請客服確認模型與分組權限，不要反覆換 Key。

<Accordion title="詳細原因（可略過）">

403 表示這次請求被拒絕。常見原因包括：Key 無權使用所選分組、啟用了模型限制、IP 白名單不符合、帳戶狀態不可用；也可能由上游模型服務拒絕。

先核對 Key 的分組、模型限制與 IP 白名單，再用一條簡短文字驗證。若持續出現，請提供 Request ID、模型、時間和錯誤原文；高頻重試或不斷建立 Key 無法排除存取限制。

</Accordion>

## 404 Not Found／請求位址錯誤

從[軟體教學](/zh-TW/tools)重新複製位址，不要自行加路徑。

<Accordion title="詳細原因（可略過）">

優先檢查：

- Base URL 是否被拼成 `/v1/v1/...`。
- 用戶端是否已自動補上 `/v1` 或具體路徑。

不同工具的位址規則不同，請用對應的[工具教學](/zh-TW/tools/)。

模型不可用通常不是 404。模型不在目前 Key 分組、目前不可用或暫時沒有可用服務時，更常見 `503`／`no available channel`。

</Accordion>

## 429 Too Many Requests

等目前請求結束，減少同時執行的程式再試一次，仍失敗就找客服。

<Accordion title="詳細原因（可略過）">

429 可能來自平台的模型頻率限制，也可能是模型服務的短期限流。像 `Concurrency limit exceeded for user` 的原文通常是上游或用戶端自身的同時請求數限制，不能只憑狀態碼判斷 API Key 壞了。

- 降低同時請求數；有 `Retry-After` 時優先依它等待，沒有時再用含隨機抖動的指數退避。
- 不要讓多個程式以同一把 Key 同時高頻重試。
- 低頻仍持續出現時，提供 Request ID 以便確認服務可用性。

</Accordion>

## 500、502、503、504 或 524

等 10～30 秒只試一次，仍失敗就聯絡客服。包含 `not implemented` 時按本頁第一項處理。

<Accordion title="詳細原因（可略過）">

除前述 `not implemented` 協定錯誤外，這些狀態通常代表處理失敗、連線中斷、服務繁忙或等候超時，不一定是 Key 或提示詞錯誤。

| 狀態 | 建議處理 |
| --- | --- |
| `500`／`502`／`503` | 等待 10–30 秒後只重試一次；持續發生時提交 Request ID。 |
| `504`／`524` | 可行時縮短上下文、工具呼叫或輸出長度，稍後再試。 |

同一模型連續失敗時，請先暫停後續長任務，保留現場資訊後聯絡支援。

</Accordion>

## `no available channel`／目前模型沒有可用服務

確認模型廣場目前分組有該模型。仍報錯就找客服，不要因此重複儲值或建 Key。

<Accordion title="詳細原因（可略過）">

這表示目前 Key 使用的分組下暫時沒有可用於該模型的服務。模型 ID 拼錯、模型未在分組提供、模型暫時不可用或服務維護都可能造成。

可稍後重試，或改用模型廣場中目前分組可見的其他模型。若持續出現，提交模型名、Request ID 與時間即可；此訊息與儲值額度或重建 Key 無關。

</Accordion>

## `Concurrency limit exceeded for user`

等目前請求結束，減少同時執行的任務後再試，通常不用重建 Key。

<Accordion title="詳細原因（可略過）">

帳戶目前的活躍請求數已達上限。等待進行中的請求結束、降低用戶端同時請求數後再試；僅憑此錯誤不需要停用或重建 API Key。

</Accordion>

## 長對話或工具呼叫錯誤

### `Invalid signature in thinking block`

目前對話保存的推理內容無法再驗證，常見於長對話恢復、用戶端狀態改變或相容性變動。請新建對話、更新用戶端，並避免在多台裝置繼續同一對話；反覆重試原對話通常無法恢復。

### `previous_response_id is only supported on Responses WebSocket v2`

用戶端正在以不支援的連線方式續接先前回應。請新建對話、關閉實驗性的對話續接／回應重用功能，或更新用戶端。

### `Content block not found`

用戶端未收到預期的完整內容片段，常見於長對話、工具呼叫或串流中斷。請先新建對話、縮短輸入同時請求數送簡單測試；若仍有異常，再暫時關閉非必要的工具呼叫，並向支援提供 Request ID、發生時間、模型與錯誤原文。我們會據此核查服務狀態。

## 帳戶有額度但 Key 顯示額度不足

請檢查帳戶餘額、API Key 的額度上限、有效期與金鑰分組。單次提示也可能來自 Key 額度上限、Key 到期或分組規則，請先確認這些資訊再決定是否儲值；持續出現時請提供 Request ID 供查核。

## 錯誤後會自動成功嗎？

錯誤不代表平台稍後一定會完成請求。一般呼叫不承諾平台層級的自動重試；若用戶端或程式再次傳送，通常會產生新的 Request ID。

請以對應 Request ID 的最終紀錄以及用戶端是否收到完整內容判斷結果。懷疑重複扣費時，提供相關 Request ID 與時間。

## 聯絡支援時請一次提供

```text
軟體名稱：
發生時間：
模型與分組：
報錯原文或截圖：
請求編號（有就填）：
```

不知道的留空。不要傳完整 Key、密碼或驗證碼。
