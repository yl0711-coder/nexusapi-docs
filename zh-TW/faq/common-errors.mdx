title: "API 呼叫常見問題集"
---

本頁涵蓋在 Claude Code、Codex CLI、Cursor、VS Code 外掛或自訂程式中呼叫 API 時常見的錯誤。

## 遇到錯誤時，你應該先做什麼？

建議依照以下順序處理：

1. 儲存錯誤原始文字和請求ID。
2. 等10~30秒再試一次。
3. 如果同一個會話一直失敗，請在建立新會話後再試一次。
4. 確認型號名稱、請求介面和用戶端版本是否正確。
5. 如果仍未通過，請依照本頁末尾的檢查清單提交題目。

請勿在短時間內高頻率重試，否則可能會觸發頻率限制並導致重複性任務。

## 500、502、503、504 或 524 有什麼問題？

這些狀態通常表示服務暫時忙碌、連線中斷或回應逾時，並不一定代表你的 API 金鑰或請求本身有問題。

| 狀態代碼 | 常見意義 | 建議 |
| --- | --- | --- |
| 500 | 請求處理失敗 | 稍後再考; 當請求 ID 持續存在時，請提交 |
| 502 | 收到無效或不完整的回應 | 等10~30秒再試一次 |
| 503 | 該服務暫時無法提供 | 請稍後再試，以避免重複請求 |
| 504 / 524 | 請求等待時間太長 | 縮短輸入或稍後再試 |

若僅有一次故障且程序自動完成，通常不需要額外的處理。 如果同一型號連續多次故障，請與我們聯繫。

## 429 太多請求

這表示目前請求過多，或可用處理能力已達到暫時限制。

建議：

- 使用指數後退方法重試，例如等待2、5、10或20秒。
- 減少並行並請求頻率。
- 不要允許多個程式同時使用同一把 API 金鑰來處理高並發請求。
- 若低頻來電仍顯示429，請提供您的請求識別碼以與我們聯繫。

## 400 個壞請求

400 通常表示請求格式、參數或會話狀態與目前介面不相容。

建議依序檢查：

1. 請確認型號名稱是否正確。
2. 請求是否被送達模型支援的介面。
3. 檢查客戶端是否是最新版本。
4. 是否使用實驗參數、工具呼叫或會話延續函式。
5. 新工作階段建立後是否能恢復。

請勿重複提交相同請求且未經修改; 格式問題通常不會在重試後自動恢復。

## 思考區塊中的無效簽名

此錯誤表示目前會話中儲存的思考內容無法再次檢查，常見於長時間的會話恢復、客戶端狀態變更或不相容的會話內容。

建議：

1. 建立新會話;不要繼續還原目前的會話。
2. 把客戶端更新到最新版本。
3. 若同一工作階段跨多個裝置使用，則只能在一台裝置上繼續。
4. 如果仍有新的工作階段出現，請提交完整錯誤及請求識別碼。

這些錯誤不會透過清除模型輸出快取自動修復;最有效的處理方式通常是建立一個新的會話。

## previous_response_id 僅支援 Responses WebSocket v2

這表示用戶端正嘗試恢復先前的回應，但目前的連線方式不支援此恢復模式。

建議：

- 建立一個新會話再試一次。
- 更新客戶端。
- 關閉實驗性會話的延續或回應重用選項。
- 自訂程式應避免在一般 HTTP 請求中重複使用不支援的程式 `previous_response_id`。

## 找不到內容區塊

這通常表示客戶端預期的內容片段尚未完全接收，可能是因為長時間工作、工具呼叫或回應中斷所致。

建議先建立新工作階段並縮短輸入內容。 詳見詳細搬運方法 [找不到內容區塊](/zh-TW/faq/content-block-not-found)。

## 影像生成未啟用或模型未支援

這表示目前的型號、帳號類型或請求介面不支援所請求的功能。

請檢查：

- 文字模型不應該呼叫影像生成介面。
- 影像模型應使用文件中指定的影像介面。
- 檢查型號名稱是否拼寫正確。
- 目前的模型是否支援你使用的圖片、工具呼叫或參數？

單純重試通常無法解決該能力無法支援的問題。

## 平衡不足，但主機平衡正常

如果 NexusAPI 主控台顯示餘額足夠，請不要立即充值。 此提示也可能表示所請求的服務資源暫時無法使用。

請儲存請求ID，稍等片刻後再試一次; 如果持續，請聯絡我們確認。

## 為什麼錯誤會先出現在日誌中，然後任務才在後來完成？

系統會在部分可恢復錯誤後自動重試，因此同一個請求 ID 可能同時擁有一個錯誤記錄與一個成功紀錄。

在決定最終結果時，請參考同一請求ID的最後紀錄，以及客戶是否已收到完整內容。

## 申請失敗會被收費嗎？

當沒有有效內容產生時，錯誤紀錄通常會顯示為 0 消耗。

以下情況需分別檢查：

- 服務已經產生內容，但客戶端在接收時斷線。
- 相同的請求 ID 先會造成錯誤，然後自動完成。
- 客戶端會自行發起新的請求。

若懷疑有重複或失敗的扣款，請提供您的申請ID及發生時間，我們將核實申請紀錄。 不要傳送完整的 API 金鑰。

## 401 未經授權

常見原因：

- API 金鑰輸入錯誤或缺失 `Bearer ` 前綴。
- API 金鑰已被刪除、停用或無效。
- 該請求使用了錯誤的存取地址。

請再次複製 API 金鑰並檢查請求標頭：

```http
Authorization: Bearer <你的 API Key>
```

## 聯絡我們時需要提供什麼？

為了更快找到，請嘗試提供：

- 請求身分證。
- 錯誤時間與時區。
- 原始文字或截圖錯誤。
- 所使用的模型。
- 所用工具與版本。
- 例如請求介面 `/v1/messages`、`/v1/chat/completions` 或者 `/v1/responses`。
- 問題是這種情況是零星發生、持續發生，還是只影響特定療程。

請勿提交完整的 API 金鑰、密碼、隱私資料或完整的商業內容。 API 金鑰最多可提供最後 6 位元。
