首先，選擇離你最近的現象。 遇到呼叫錯誤時，請先儲存請求 ID 及完整錯誤文字。

## 存取與配置

- **第一次使用該從哪裡開始？**
  繼續閱讀[5分鐘內快速開始](/zh-TW/guide/quick-start)。

- **應該填入哪個基礎網址？**
  不同客戶的費率可能不同，請查證[存取方法概述](/zh-TW/guide/integration-overview)。

- **為什麼會出現404？**
  檢查地址是否已形成 `/v1/v1/...`，以及客戶端是否自動串接請求路徑。

- **我能不能在建立之後不能使用 API 金鑰？**
  檢查金鑰狀態、數量、分組、型號 ID 及 `Authorization: Bearer` 格式。

## 模型、分組與成本

- **如何確認一個團體是否能使用目標模型？**
  存在[模型廣場](https://nexusapi.link/pricing)依群組篩選並複製準確的型號識別碼。

- **一個請求會消耗多少？**
  在主控台使用日誌中查看輸入、輸出、快取和花費。 詳見田野描述[劑量與日誌描述](/zh-TW/billing/usage-and-billing)。

- **申請失敗會被收費嗎？**
  若未產生有效內容，錯誤通常為零;若有中斷或後續嘗試，則必須使用請求 ID 進行驗證。

- **為什麼餘額保持正常，但配額卻不足？**
  同時檢查帳戶餘額、API 金鑰限制與群組; 請求 ID 持續存在時提交。

## 召喚錯誤

- **400、401、429、500、502、503、504、524是什麼？**
  景觀[API 呼叫常見問題集](/zh-TW/faq/common-errors)。

- **突然無法繼續長時間的對話？**
  儲存原始錯誤文字並建立新的會話進行驗證; 不要反覆提交相同的申請。

- **犯錯後，任務又成功了？**
  後續嘗試可能會發生;請參考最終記錄中相同請求 ID 及客戶的最終結果。

## 盡快尋求幫助

如果無法判斷問題類型，請按壓[自我檢查問題](/zh-TW/faq/self-check)完成最低驗證並一次性提交：

- 請求識別碼
- 發生時間與時區
- 用戶端與版本
- 模型與請求介面
- 原文完全錯誤
- 問題是這種情況是偶爾發生還是持續發生

請勿提交完整的 API 金鑰、密碼或私人資料。
