This page configures Codex CLI with a NexusAPI key, not your ChatGPT password.

## 1. Install Codex

Open PowerShell on Windows or Terminal on Mac. Run only your system's installer. Skip this if installed.

<Tabs>
<Tab title="Windows PowerShell">
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```
</Tab>
<Tab title="macOS / Linux / WSL">
```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```
</Tab>
</Tabs>

Reopen the terminal and check the version. Continue only when a version number appears; fix installation first if the command is missing.

```bash
codex --version
```

## 2. Save the address and model

[Create a key](/en/guide/api-key), select its group in [Model Square](https://nexusapi.link/pricing), and copy a Codex / Responses-compatible model name. Open the user configuration:

<Tabs>
<Tab title="Windows PowerShell">
```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex" | Out-Null
notepad "$env:USERPROFILE\.codex\config.toml"
```
</Tab>
<Tab title="macOS / Linux / WSL">
```bash
mkdir -p ~/.codex
nano ~/.codex/config.toml
```
</Tab>
</Tabs>

In nano, save with `Ctrl + O`, Enter, then exit with `Ctrl + X`. In Windows Notepad use `Ctrl + S`. Keep the filename `config.toml`, not `.txt`.

Paste into an empty file, replacing only `YOUR_MODEL_ID`:

```toml
model_provider = "nexusapi"
model = "YOUR_MODEL_ID"

[model_providers.nexusapi]
name = "NexusAPI"
base_url = "https://nexusapi.link/v1"
env_key = "NEXUSAPI_API_KEY"
wire_api = "responses"
```

Back up existing configuration. Keep `model` and `model_provider` at the top, then add or update `[model_providers.nexusapi]` without duplicate sections. You can use [CC Switch](/en/tools/cc-switch) instead. Do not put the key in this file.

## 3. Set and save your API key

Replace only `YOUR_API_KEY` with your complete key. The Windows commands set both the current terminal and persistent user environment.

<Tabs>
<Tab title="Windows PowerShell">
```powershell
$env:NEXUSAPI_API_KEY = "YOUR_API_KEY"
[Environment]::SetEnvironmentVariable("NEXUSAPI_API_KEY", $env:NEXUSAPI_API_KEY, "User")
```
</Tab>
<Tab title="macOS (Zsh)">
```bash
touch ~/.zshrc
nano ~/.zshrc
```

Add the next line at the end of the file, replacing an existing value of the same variable rather than duplicating it. Save and reopen the terminal.

```bash
export NEXUSAPI_API_KEY='YOUR_API_KEY'
```
</Tab>
<Tab title="Linux / WSL (Bash)">
```bash
nano ~/.bashrc
```

Add the next line at the end of the file, replacing an existing value of the same variable rather than duplicating it. Save and reopen the terminal.

```bash
export NEXUSAPI_API_KEY='YOUR_API_KEY'
```
</Tab>
</Tabs>

The examples use Mac's default Zsh and Linux Bash. Other shells need their own startup file; ask support if unsure. Keep keys out of projects and screenshots.

## 4. Start and test

Open a terminal in your own project and run:

```bash
codex
```

Use `/status` to check your model and the NexusAPI provider. Send “Reply only: connection successful. Do not modify files.” A complete reply and a record in [Usage Logs](https://nexusapi.link/usage-logs/common) confirm setup. The test uses a little credit.

## 5. Common problems

For `Missing environment variable`, repeat step 3. For an unavailable model, recopy a Codex-compatible name from your group. See [troubleshooting](/en/faq/self-check) for other errors.

An editor launched from the Mac Dock may not inherit terminal variables. Verify the CLI first; for the Codex extension, launch the editor from the configured terminal with `code .` or `cursor .`. Keep keys out of project settings.
