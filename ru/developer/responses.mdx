`/v1/responses` — не универсальный «новый API чата». В NexusAPI он предназначен прежде всего для кастомного Provider из [руководства Codex CLI](/ru/tools/codex-cli), либо для модели, у которой `supported_endpoint_types` в `/v1/models` содержит `openai-response`.

<Warning>
**Сначала подтвердите поддерживаемый протокол**

Если `supported_endpoint_types` не содержит `openai-response`, не используйте `/v1/responses`. При `status_code=500, not implemented` используйте указанный для этой модели протокол, а не считайте ошибку временной и повторяйте запрос.
</Warning>

## Endpoint и область применения

```text
POST https://nexusapi.link/v1/responses
```

| Сценарий | Рекомендуемый подход |
| --- | --- |
| Codex CLI | Используйте Provider `wire_api = "responses"` из [руководства Codex CLI](/ru/tools/codex-cli) |
| Другое приложение с моделью, у которой `supported_endpoint_types` содержит `openai-response` | Используйте его Responses client/Schema и сначала проверьте минимальный запрос |
| Обычное OpenAI-совместимое текстовое приложение | Используйте [Chat Completions](/ru/developer/openai-compatible); не переключайтесь лишь из-за новизны API |
| Модель без `openai-response` | Используйте протокол Chat Completions или Messages, указанный в `supported_endpoint_types`, а не этот endpoint |

## Минимальный запрос для проверки

Только после подтверждения модели проверьте связь так:

```bash
curl 'https://nexusapi.link/v1/responses' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -d '{
    "model": "YOUR_RESPONSES_MODEL_ID",
    "input": "Ответьте только: соединение успешно"
  }'
```

`input` — не то же поле, что `messages` в Chat Completions; ответ нельзя разбирать как `choices[0].message`. Полные поля, streaming-события и структуру результата смотрите в официальной Schema клиента.

## Основные настройки Codex CLI

```toml
model_provider = "nexusapi"
model = "YOUR_MODEL_ID"

[model_providers.nexusapi]
base_url = "https://nexusapi.link/v1"
env_key = "NEXUSAPI_API_KEY"
wire_api = "responses"
```

Храните key в переменной окружения `NEXUSAPI_API_KEY`, а не в `config.toml` или `auth.json`. Установка, переменные ОС и проверка приведены в [руководстве Codex CLI](/ru/tools/codex-cli).

## Что проверить сначала

1. Группа key содержит модель, а ID полностью совпадает с каталогом.
2. Клиент действительно обращается к `/v1/responses`, а не `/v1/v1/...`.
3. `supported_endpoint_types` модели содержит `openai-response`; если нет, используйте указанный совместимый протокол.
4. Сохраните Request ID, версию клиента и полный текст ошибки, затем выполните [самопроверку](/ru/faq/self-check).
