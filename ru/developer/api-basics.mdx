Здесь описаны правила, общие для всех вызовов моделей, и объясняется, **какой протокол выбрать и как безопасно начать**.

<Info>
**Сначала подтвердите возможности**

Доступные модели зависят от группы API key, ограничений модели и текущего состояния сервиса. Общий каталог не гарантирует, что конкретная модель доступна для вашей ключа.
</Info>

## Три обязательных значения

| Значение | Где получить | Назначение |
| --- | --- | --- |
| Base URL | Эта страница | Направляет запросы SDK или клиента в NexusAPI |
| API key | Console → Token management | Идентифицирует вызывающего и доступные группы |
| ID модели | Каталог моделей или `/v1/models` | Выбирает модель для запроса |

Для стандартного клиента в стиле OpenAI используйте:

```text
https://nexusapi.link/v1
```

В ручном HTTP-запросе передавайте ключ через `Authorization`:

```http
Authorization: Bearer YOUR_API_KEY
```

Не помещайте полный key в frontend, скриншоты, чат или Git-репозиторий. Правила URL у клиентов различаются: Claude Code использует адрес без `/v1`, Codex CLI — настройку Provider. Следуйте соответствующему [руководству по клиентским инструментам](/ru/tools/index).

## Получить модели, видимые этому key

```bash
curl 'https://nexusapi.link/v1/models' \
  -H 'Authorization: Bearer YOUR_API_KEY'
```

Скопируйте ID из `data[].id`. Это модели, **видимые сейчас данному key**, а не весь каталог. `data[].supported_endpoint_types` перечисляет протоколы запросов, доступные для этой модели. Используйте только путь с указанным типом: `openai` для Chat Completions, `anthropic` для Messages, `openai-response` для Responses и `image-generation` для генерации изображений. Если указано несколько типов, выберите подходящий вашему клиенту.

## Выбрать правильный протокол

| Цель | Путь | Когда использовать |
| --- | --- | --- |
| Текст, чат и streaming в стиле OpenAI | `POST /v1/chat/completions` | Модели, у которых `supported_endpoint_types` содержит `openai`; большинство собственных приложений, OpenAI SDK и обычных клиентов |
| Нативный Anthropic / Claude Code | `POST /v1/messages` | Модели, у которых `supported_endpoint_types` содержит `anthropic` |
| Provider Codex | `POST /v1/responses` | Только по [руководству Codex CLI](/ru/tools/codex-cli) и для модели, у которой `supported_endpoint_types` содержит `openai-response` |
| Генерация изображений | `POST /v1/images/generations` | Модели изображений, у которых `supported_endpoint_types` содержит `image-generation` |

Одинаковое имя модели не означает поддержку любого формата запроса. Подтвердите протокол в [матрице возможностей](/ru/developer/capability-matrix), затем прочитайте:

- [Chat Completions](/ru/developer/openai-compatible)
- [Anthropic Messages](/ru/developer/anthropic-messages)
- [Responses / Codex](/ru/developer/responses)
- [Работа с моделями изображений](/ru/guide/image-generation)

## Минимальная проверка и повторы

1. Получите список моделей, затем отправьте один короткий текстовый или минимальный image-запрос.
2. Подтвердите ID модели, группу key и путь до добавления полей, streaming или пакетных задач.
3. При ошибке сохраните текст ошибки, время и Request ID. Не повторяйте неподтверждённый запрос с высокой частотой.

Для `401` сначала проверьте key. Для `404` — отсутствие или повтор `/v1`. Для `400` — модель, протокол и поля. Подробнее — в [самопроверке](/ru/faq/self-check).
