---

**Если список заполнен, ключ можно использовать только с перечисленных IP. Пустое поле означает отсутствие ограничения по IP. Действительный ключ всё равно необходим.**

Проверяется IP источника, определённый платформой. Прокси и изменения сети могут влиять на результат; белый список не заменяет безопасное хранение ключа.

Настройка удобна для компьютеров и серверов с постоянным публичным IP. Если адрес динамический или вы часто меняете сеть, сначала уточните, насколько стабилен исходящий IP.

## 1. Определите нужный IP

Укажите **публичный исходящий IP системы, которая отправляет запросы к NexusAPI**, а не IP сайта NexusAPI и не локальный адрес компьютера.

| Где используется ключ | Какой IP указать |
| --- | --- |
| Claude Code, Codex или другое приложение на компьютере | Публичный IP, с которого этот компьютер выходит в интернет |
| Сервер компании, собственное приложение или контейнер | Фактический исходящий IP сервера; уточните у администратора |
| Прокси, VPN или сторонний облачный инструмент | IP узла, пересылающего запросы; он может отличаться от IP компьютера, уточните у поставщика |

Не указывайте `192.168.x.x`, `10.x.x.x`, `127.0.0.1`, домен, URL или номер порта.

**Не знаете публичный IP?** Выполните проверку на компьютере или сервере, где работает приложение, с теми же настройками сети и прокси:

Windows: откройте PowerShell и выполните:

```powershell
curl.exe -4 https://api.ipify.org
```

macOS / Linux: откройте терминал и выполните:

```bash
curl -4 https://api.ipify.org
```

Полученный адрес — публичный IPv4 именно этого проверочного запроса. [ipify](https://www.ipify.org/) — сторонний сервис определения публичного IP. Ему не нужен API-ключ: никогда не отправляйте его туда. Если проверка не проходит, обратитесь к администратору или сетевому провайдеру.

Если у приложения отдельный прокси, оно работает в облаке или использует IPv6, этот IPv4 может не совпадать с его исходящим адресом. Сначала подтвердите фактический источник запросов.

## 2. Откройте список и сохраните

1. Откройте [Ключи API](https://nexusapi.link/keys) и найдите ключ приложения.
2. Нажмите **Изменить** в его строке.
3. Разверните **Расширенные настройки** и найдите **Белый список IP (поддерживает CIDR)**.
4. Введите реальные публичные IP, **по одному на строку**.
5. Нажмите **Сохранить изменения**.

При создании ключа используется то же поле. Заново копировать или заменять ключ не нужно. Изменение затронет все приложения и коллег, использующих этот ключ: проверьте это до сохранения.

## 3. Укажите один или несколько IP

**Разрешить один IP:**

```text
203.0.113.10
```

**Для нескольких IP используйте отдельную строку для каждого адреса, а не запятые, точки с запятой или пробелы.**

```text
203.0.113.10
198.51.100.20
```

Это адреса для примера, а не готовая настройка. Замените их своими реальными публичными IP. Не добавляйте `https://`, `:443` или `*`.

## 4. Настройте записи CIDR

### Что означает CIDR

**CIDR задаёт один IP или целый диапазон одной строкой: `IP-адрес/длина префикса`.** Например, `203.0.113.0/24`.

Число после косой черты определяет размер диапазона. **Это не порт и не количество разрешённых IP.** `/24` не означает 24 IP. В пределах одного семейства адресов меньшее число разрешает более широкий диапазон.

Для одного компьютера или сервера с постоянным исходящим IP достаточно указать сам публичный IP. CIDR используйте для диапазона, который компания явно предоставила.

### Примеры и фактические диапазоны

| Пример | Разрешённый диапазон |
| --- | --- |
| `203.0.113.10` или `203.0.113.10/32` | Только `203.0.113.10`: 1 адрес IPv4 |
| `203.0.113.0/28` | От `203.0.113.0` до `203.0.113.15`: 16 адресов IPv4 |
| `203.0.113.0/24` | От `203.0.113.0` до `203.0.113.255`: 256 адресов IPv4 |
| `2001:db8::10` или `2001:db8::10/128` | Только этот адрес IPv6 |

Это примеры, а не готовые настройки. Не добавляйте `/24` к своему IP без необходимости: так разрешение расширяется с одного адреса на всю подсеть.

### Что ввести в поле

Если компания разрешила целую подсеть и отдельный сервер, укажите в белом списке IP две строки:

```text
203.0.113.0/24
198.51.100.20/32
```

Замените их реальными значениями, подтверждёнными администратором, и сохраните. Обычные IP и CIDR можно смешивать, **по одной записи на строку. Совпадения с любой записью достаточно для проверки IP.** Остальные ограничения ключа, модели и квоты сохраняются.

Несколько несмежных IP просто укажите отдельными строками. Записи `203.0.113.*`, `203.0.113.10-203.0.113.20` и отдельное `/24` не поддерживаются. Для перевода диапазона в CIDR попросите администратора предоставить точные записи, не расширяйте диапазон самостоятельно.

IPv4 и IPv6 можно смешивать. Разрешение IPv4 не разрешает IPv6 автоматически. В сети с поддержкой IPv6 можно проверить адрес командой `curl -6 https://api6.ipify.org`; в Windows используйте `curl.exe`. Неудачная проверка не доказывает, что приложение использует IPv4.

**Не вводите `0.0.0.0/0` или `::/0` ради устранения ошибки.** Они разрешают соответственно все источники IPv4 или IPv6, лишая ограничение смысла. Если диапазон неизвестен, спросите администратора.

## 5. Проверьте работу и возможные ошибки

Отправьте один короткий запрос из привычного приложения. Нормальный ответ означает, что именно этот запрос прошёл проверку IP, но не подтверждает другие источники. Тест модели оплачивается как обычный вызов.

Если ошибка сообщает, что IP не разрешён, или текст ошибки `403` прямо указывает на ограничение IP, проверьте:

1. Изменён именно ключ приложения и нажата кнопка сохранения.
2. Каждый IP записан на отдельной строке, без URL, порта или лишних символов.
3. Не изменился ли публичный IP после смены Wi-Fi, мобильной точки доступа, прокси или выхода сервера.
4. Не использует ли приложение IPv6 или сторонний сервер для отправки запросов.

Если отказ сохраняется, передайте поддержке название приложения, время, имя ключа и точный текст ошибки. Попросите проверить IP источника, определённый для этого запроса. Полный ключ не отправляйте. Не каждый `403` связан с белым списком; другие причины описаны в [частых ошибках](/ru/faq/common-errors).

## 6. Измените или отключите ограничение

Откройте редактирование того же ключа. Добавьте адрес на новой строке или замените старый, затем сохраните.

Чтобы отключить ограничение, удалите **всё содержимое** списка и сохраните. Ограничение IP исчезнет, но действительный ключ останется обязательным. Если компания требует ограничивать источники, сначала получите разрешение администратора.

Белый список не заменяет защиту ключа. При утечке [немедленно отключите старый ключ](/ru/guide/api-key), а не просто измените список IP.
