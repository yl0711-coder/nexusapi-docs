---
title: "Проверьте проблему самостоятельно"
---

Если звонок не работает, сначала перейдите на эту страницу, чтобы пройти базовую проверку. Большинство конфигураций или случайных проблем можно определить за считанные минуты.

## Шаг 1: Сохранить сайт

Перед закрытием клиента или повторным запросом сохраните:

- Полная ошибка в оригинальном тексте
- Запрос ID
- Время и часовой пояс
- Используемая модель
- Клиент и используемая версия
- Например, интерфейсы запросов `/v1/responses`

Не отправляйте полные API-ключи, пароли, личные данные или полный бизнес-контент.

## Шаг 2: Определите тип задачи

| Явление | Приоритетные проверки |
| --- | --- |
| 401 | API Key、`Bearer` Префикс, адрес запроса |
| 404 | Проверьте, дублируется ли базовый URL или отсутствует `/v1` |
| 400 | Модели, интерфейсы, параметры и состояния сессии |
| 429 | Параллельность и частота запросов |
| 500 / 502 / 503 | Подождите 10~30 секунд и попробуйте снова |
| 504 / 524 | Запросите контент, время ожидания и статус сервиса |
| Недостаток баланса | Баланс консоли, количество ключей и группировка |

Для конкретных значений см. ниже [Часто задаваемые вопросы по вызовам API](/ru/faq/common-errors)。

## Шаг 3: Проведите минимальную проверку

1. Убедитесь, что консольный баланс и API Key работают корректно.
2. Скопируйте ID модели из квадрата модели.
3. Создайте новую сессию и отправьте короткое сообщение.
4. Попробуйте только один раз и запишите новый Request ID.
5. Проверьте, показывает ли журнал использования консоли соответствующий запрос.

Если новая сессия проходит успешно, проблема обычно связана с исходным состоянием сессии или содержанием запроса; Если даже самый маленький запрос продолжает отклоняться, пожалуйста, задайте вопрос.

## Предоставляется при обращении в службу поддержки

Пожалуйста, предоставьте следующее немедленно:

```text
发生时间（含时区）：
Request ID：
客户端及版本：
模型：
请求接口：
错误原文：
偶发还是持续发生：
是否已用新会话验证：
```

Чем полнее информация, тем быстрее определяется местонахождение. API Key может предоставлять до последних 6 бит.
