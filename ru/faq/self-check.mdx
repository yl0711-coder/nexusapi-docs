Большинство ошибок настройки и временных сбоев можно локализовать за несколько минут. Сначала сохраните доказательства, затем выполните только один минимальный тест с низкой частотой.

## 1. Сохраните контекст ошибки

До закрытия клиента или повтора сохраните:

- полный текст ошибки и Request ID;
- время и часовой пояс;
- ID модели, endpoint и использование streaming;
- клиент / SDK и версию.

Не отправляйте полный API-ключ, пароль, личные данные или весь деловой контент.

## 2. Определите класс проблемы

| Симптом | Проверить сначала |
| --- | --- |
| 401 | Ключ, префикс `Bearer`, URL. |
| 403 | Группу, ограничение модели, список IP, аккаунт, отказ upstream. |
| 404 | Base URL, путь, дубликат или отсутствие `/v1`. |
| 400 | Модель, протокол, параметры, состояние сессии. |
| 429 | Параллельность и частоту; соблюдайте `Retry-After`. |
| 500 / 502 / 503 | Подождите 10–30 секунд и повторите только один раз. |
| 504 / 524 | Размер запроса, время ожидания, состояние сервиса. |
| `500, not implemented` | Не повторяйте: проверьте Responses-вызов модели Claude. |
| `no available channel` | ID модели, группу токена и текущую доступность. |

Подробности — в [частых ошибках API](/ru/faq/common-errors).

## 3. Минимальный тест

1. Проверьте баланс и состояние ключа в консоли.
2. Скопируйте ID модели заново из каталога.
3. Откройте новую сессию и отправьте короткий текст.
4. Повторите не более одного раза и сохраните новый Request ID.
5. Проверьте соответствующую запись журнала.

## Обращение в поддержку

Передайте эти сведения одним сообщением:

```text
Время (с часовым поясом):
Request ID:
Клиент и версия:
Модель:
Endpoint:
Полный текст ошибки:
Проблема периодическая или постоянная:
Проверка в новой сессии:
```

Если нужно идентифицировать ключ, укажите не более шести последних символов.
