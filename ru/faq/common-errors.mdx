title: "Часто задаваемые вопросы по вызовам API"

На этой странице рассматриваются распространённые ошибки, возникающие при вызове API в Claude Code, Codex CLI, Cursor, плагинах VS Code или пользовательских программах.

## Что делать в первую очередь, когда вы столкнулись с ошибкой?

Рекомендуется обрабатывать их в следующем порядке:

1. Сохраните исходный текст ошибки и запрос ID.
2. Подождите 10~30 секунд и попробуйте снова.
3. Если одна и та же сессия продолжает не работать, попробуйте снова после создания новой сессии.
4. Убедитесь, что название модели, интерфейс запроса и версия клиента правильны.
5. Если всё равно не получается, задайте вопрос согласно чек-листу в конце этой страницы.

Пожалуйста, не повторяйте на высокой частоте в короткий срок, так как это может вызвать ограничения по частоте и привести к повторяющимся заданиям.

## В чём проблема с 500, 502, 503, 504 или 524?

Эти состояния обычно указывают на временную загруженность сервиса, прерывание соединения или время отклика истекло, и это не обязательно означает, что проблема возникла с вашим API Key или самим запросом.

| Код статуса | Общее значение | Предложение |
| --- | --- | --- |
| 500 | Обработка запроса была неудачной | Перепробуйте позже; Отправляйте ID запроса, когда он сохраняется |
| 502 | Получение некорректных или неполных ответов | Подождите 10~30 секунд и попробуйте снова |
| 503 | Услуга временно недоступна | Попробуйте позже, чтобы избежать повторных запросов |
| 504 / 524 | Попросите, чтобы время ожидания было слишком долгим | Сократите ввод или попробуйте позже снова |

Если произошёл только один сбой и процесс автоматически завершается после него, обычно не требуется дополнительное обрабатывание. Если одна и та же модель несколько раз подряд выходит из строя, пожалуйста, свяжитесь с нами.

## 429 Слишком много запросов

Это указывает на слишком много запросов или о том, что доступная вычислительная мощность достигла временного лимита.

Рекомендации:

- Попробуйте использовать экспоненциальные методы отступления, например, подождите 2, 5, 10 или 20 секунд.
- Сократите совместность и частоту запросов.
- Не позволяйте нескольким программам одновременно использовать один и тот же ключ API для запросов с высокой параллелью.
- Если низкочастотные звонки всё ещё показывают 429, пожалуйста, укажите свой Request ID, чтобы связаться с нами.

## 400 Bad Request

400 обычно указывает на несовместимость формата запроса, параметров или состояния сессии с текущим интерфейсом.

Рекомендуется проверять в следующем порядке:

1. Проверьте, правильное ли название модели.
2. Будет ли запрос отправлен на интерфейс, поддерживаемый моделью.
3. Проверьте, является ли клиент последней версией.
4. Используются ли экспериментальные параметры, вызовы инструментов или функции продолжения сессии.
5. Можно ли восстановить новую сессию после её создания.

Не подавайте один и тот же запрос без изменений; Проблемы с форматированием обычно не восстанавливаются автоматически после повторной попытки.

## Неверная подпись в блоке мышления

Эта ошибка означает, что содержимое мыслей, сохранённое в текущей сессии, нельзя проверить снова, что часто встречается при восстановлении длительной сессии, изменении состояния клиента или несовместимом содержимом сессии.

Рекомендации:

1. Создайте новую сессию; не продолжайте восстанавливать текущую сессию.
2. Обновите клиент до последней версии.
3. Если одна и та же сессия используется на нескольких устройствах, её можно продолжить только на одном устройстве.
4. Если новые сессии всё ещё отображаются, пожалуйста, отправьте полную ошибку и запрос ID.

Эти ошибки не исправляются автоматически при очистке кэша выхода модели; наиболее эффективная обработка обычно происходит при создании новой сессии.

## previous_response_id поддерживается только на WebSocket версии Responses v2

Это означает, что клиент пытается возобновить предыдущий ответ, но текущий способ подключения не поддерживает этот режим возобновления.

Рекомендации:

- Создайте новую сессию и попробуйте снова.
- Обновите клиент.
- Отключите опцию возобновления экспериментальной сессии или повторного использования ответа.
- Пользовательские программы должны избегать повторного использования неподдерживаемых в обычных HTTP-запросах `previous_response_id`。

## Блок контента не найден

Обычно это означает, что ожидаемый фрагмент контента клиента не был полностью получен, возможно, из-за долгих сессий, вызовов инструментов или прерванных ответов.

Рекомендуется сначала создать новую сессию и сократить вводный контент. См. подробные методы обработки [Блок контента не найден](/ru/faq/content-block-not-found)。

## Генерация изображений не включена или модель не поддерживается

Это означает, что текущая модель, тип аккаунта или интерфейс запроса не поддерживают запрошенные возможности.

Пожалуйста, проверьте:

- Текстовые модели не должны вызывать интерфейс генерации изображений.
- Модели изображений должны использовать интерфейс изображения, указанный в документе.
- Проверьте, правильно ли написано название модели.
- Поддерживает ли текущая модель изображения, вызовы инструментов или параметры, которые вы используете?

Простая повторная попытка обычно не решает проблемы, которые не поддерживают возможности.

## Недостаточный баланс, но консольный баланс нормальный

Если консоль NexusAPI показывает достаточный баланс, не перезаряжайте сразу. Этот запрос также может указывать на то, что запрошенные сервисные ресурсы временно недоступны.

Пожалуйста, сохраните ID запроса, подождите немного, затем попробуйте снова; Свяжитесь с нами для проверки, если проблема сохраняется.

## Почему ошибка появилась сначала в журнале, а затем задача была выполнена позже?

Система автоматически повторит попытку после частичных восстанавливаемых ошибок, поэтому один и тот же идентификатор запроса может содержать одну запись ошибки и одну запись успеха.

При определении итогового результата, пожалуйста, ссылайтесь на последнюю запись того же идентификатора запроса и на получение клиента полного содержания.

## Будет ли неудачный запрос списать?

Если не генерируется корректный контент, ошибки обычно отображаются как 0 потребления.

Следующие ситуации необходимо проверять отдельно:

- Сервис сгенерировал контент, но клиент отключается во время приёма.
- Один и тот же идентификатор запроса сначала вызывает ошибку, а затем автоматически завершается.
- Клиент самостоятельно инициирует новый запрос.

Если подозреваются дублирующие или неудачные платежи, пожалуйста, укажите свой идентификатор запроса и время происшествия, и мы проверим записи запроса. Не отправляйте полный API Key.

## 401 Несанкционированный

Распространённые причины:

- Ключ API введён неправильно или отсутствует `Bearer ` Префикс.
- Ключ API был удалён, отключён или недействителен.
- Запрос использовал неправильный адрес доступа.

Пожалуйста, скопируйте ключ API снова и проверьте заголовок запроса:

```http
Authorization: Bearer <你的 API Key>
```

## Что вы должны предоставить при обращении к нам?

Чтобы найти их быстрее, старайтесь предоставлять:

- Request ID。
- Ошибка во времени и часовом поясе.
- Оригинальный текст или ошибка скриншота.
- Используемая модель.
- Инструменты и используемые версии.
- Например, интерфейсы запросов `/v1/messages`、`/v1/chat/completions` Или `/v1/responses`。
- Вопрос в том, происходит ли это спорадически, постоянно или затрагивает только конкретную сессию.

Не отправляйте полные API-ключи, пароли, данные конфиденциальности или полный бизнес-контент. API Key может предоставлять до последних 6 бит.
