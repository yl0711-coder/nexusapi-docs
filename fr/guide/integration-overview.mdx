NexusAPI peut être utilisé depuis une application, un client compatible OpenAI ou un outil de développement. Les clients ne construisent pas tous l'URL de la même manière et n'utilisent pas tous le même protocole. Choisissez d'abord votre cas d'usage : ne copiez pas la configuration d'un outil dans un autre.

## Les trois vérifications préalables

1. Créez une clé API dans la console et définissez une limite adaptée.
2. Vérifiez que le groupe de cette clé contient le modèle visé.
3. Copiez l'ID exact du modèle depuis le catalogue ou depuis `/v1/models`.

## URL et protocole

| Cas | Base URL | Point de départ | Note |
| --- | --- | --- | --- |
| SDK compatible OpenAI ou programme général | `https://nexusapi.link/v1` | Chat Completions | Le SDK ajoute généralement `/chat/completions`. |
| Claude Code | `https://nexusapi.link` | Messages Anthropic | N'ajoutez pas `/v1`. |
| Codex CLI | `https://nexusapi.link/v1` | Responses | Utilisez le fournisseur personnalisé Codex. |
| Modèle d'image | `https://nexusapi.link/v1` | Images | Seulement pour un modèle explicitement compatible. |

<Warning>
Un modèle visible n'est pas forcément disponible pour chaque protocole. Consultez d'abord la [matrice des API et des capacités](/fr/developer/capability-matrix) : elle décrit les endpoints réellement documentés par NexusAPI.
</Warning>

## Vérification minimale

1. Appelez `GET /v1/models` avec la clé concernée.
2. Choisissez un ID retourné et compatible avec le protocole.
3. Envoyez une courte requête de test.
4. Vérifiez l'entrée correspondante dans le journal d'utilisation.

En cas d'échec, conservez l'erreur complète et le Request ID, puis suivez l'[auto-vérification](/fr/faq/self-check). N'envoyez pas la même tâche en boucle.
