---
title: "API des journaux d'usage"
description: "Lisez à faible fréquence les journaux NexusAPI du compte avec un jeton d'accès système."
---

`api.nexusapi.link` est une passerelle de consultation **en lecture seule**, séparée de la console et du relais de modèles. Elle lit les journaux de consommation du compte du détenteur du jeton ; elle ne peut ni appeler un modèle, ni ajouter du crédit, ni administrer le compte.

## Informations de base

| Élément | Valeur |
| --- | --- |
| Base URL | `https://api.nexusapi.link` |
| Endpoint | `GET /v1/logs` |
| Identifiant recommandé | Jeton d'accès système |
| Tri | Entrées les plus récentes en premier |

Créez un jeton dans **Console → Paramètres personnels → Générer un jeton**, puis envoyez-le uniquement ainsi :

```http
Authorization: Bearer YOUR_SYSTEM_ACCESS_TOKEN
```

<Warning>
Les appels de modèles utilisent une clé créée dans Gestion des jetons ; l'API de journaux doit utiliser un jeton d'accès système. Ce dernier ne peut pas appeler de modèle, mais il expose des données de compte et reste secret.
</Warning>

## Paramètres

| Paramètre | Rôle |
| --- | --- |
| `start_time` | Début en secondes Unix ou RFC3339. |
| `end_time` | Fin en secondes Unix ou RFC3339, jamais antérieure au début. |
| `page` | Numéro de page à partir de `1`. |
| `page_size` | Taille de page, `10` par défaut, `50` au maximum. |

Interrogez un jour ou une semaine à la fois. Les filtres serveur par modèle, groupe ou nom de clé ne sont pas disponibles ; filtrez les données de votre compte localement. `page × page_size` ne peut pas dépasser `100000`.

## Exemple

```bash
curl -G 'https://api.nexusapi.link/v1/logs' \
  -H 'Authorization: Bearer YOUR_SYSTEM_ACCESS_TOKEN' \
  --data-urlencode 'start_time=2026-06-01T00:00:00Z' \
  --data-urlencode 'end_time=2026-06-02T00:00:00Z' \
  --data-urlencode 'page=1' \
  --data-urlencode 'page_size=50'
```

Une liste `data` vide ou plus courte que `page_size` indique la dernière page. Les champs utiles incluent `time`, `token_name`, `group`, `model`, `prompt_tokens`, `completion_tokens`, `cost`, `request_id` et `request_path`.

Respectez `Retry-After` pour 429 ou 503. Planifiez des synchronisations incrémentales, pas une interrogation seconde par seconde ; conservez à la fois l'intervalle interrogé et le Request ID du modèle lors d'un rapprochement.
