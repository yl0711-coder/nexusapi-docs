---
title: "Configurer Claude Code"
description: "Installez Claude Code et connectez-le à NexusAPI avec la configuration Anthropic native."
---

Claude Code utilise le protocole Messages Anthropic. Sa Base URL NexusAPI est donc `https://nexusapi.link` : **n'ajoutez pas `/v1`**.

## 1. Installer Claude Code

Utilisez l'installeur officiel :

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

```powershell
irm https://claude.ai/install.ps1 | iex
```

Windows peut aussi utiliser `winget install Anthropic.ClaudeCode`, et macOS `brew install --cask claude-code`. Vérifiez ensuite :

```bash
claude --version
claude doctor
```

## 2. Créer une clé NexusAPI

Dans **Gestion des jetons → Ajouter un jeton**, choisissez un groupe contenant le modèle Claude voulu et définissez une limite. Vérifiez le protocole dans le catalogue ou la [matrice des capacités](/fr/developer/capability-matrix).

## 3. Configurer le compte utilisateur

| Système | Fichier |
| --- | --- |
| macOS / Linux / WSL | `~/.claude/settings.json` |
| Windows | `%USERPROFILE%\\.claude\\settings.json` |

Sur macOS, Linux, WSL ou Git Bash :

```bash
mkdir -p ~/.claude
touch ~/.claude/settings.json
```

Fusionnez ces valeurs dans `env` sans écraser vos autres réglages :

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "YOUR_NEXUSAPI_KEY",
    "ANTHROPIC_BASE_URL": "https://nexusapi.link"
  }
}
```

Conservez ce fichier dans le profil utilisateur, jamais dans le dépôt du projet.

## 4. Vérifier

Ouvrez un nouveau terminal, lancez `claude`, puis exécutez `/status`. Vérifiez que **Anthropic base URL** vaut `https://nexusapi.link` et envoyez une courte question.

## Problèmes fréquents

### `Invalid API Key · Please run /login`

Vérifiez les deux variables, le statut de la clé et le redémarrage du terminal. Ne modifiez pas les fichiers internes d'état de connexion de Claude.

### `fetch failed`

1. Envoyez une courte question normale. Si elle fonctionne, le problème concerne probablement WebFetch ou une autre fonction réseau distincte.
2. Si tous les appels échouent, lancez `claude doctor` et vérifiez l'URL avec `/status`.
3. Contrôlez DNS, pare-feu, réseau d'entreprise ou proxy de confiance pour `nexusapi.link`.
4. Ouvrez un nouveau terminal et testez une seule fois. En cas d'échec persistant, conservez version, sortie doctor, erreur complète et Request ID, puis suivez l'[auto-vérification](/fr/faq/self-check).

### État `offline`

Certaines fonctions auxiliaires testent des services séparés. Vérifiez l'URL avec `/status` et une courte requête de modèle avant de conclure à une panne NexusAPI.
