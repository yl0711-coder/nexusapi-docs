Hãy chọn hiện tượng gần nhất. Khi lỗi xảy ra, trước hết lưu toàn bộ nội dung lỗi và Request ID rồi mới thay đổi cấu hình hoặc thử lại.

## Tích hợp và cấu hình

- **Bắt đầu từ đâu?** Xem [bắt đầu nhanh](/vi/guide/quick-start).
- **Dùng Base URL nào?** Tùy client; xem [tổng quan tích hợp](/vi/guide/integration-overview).
- **Vì sao 404?** Kiểm tra URL có thành `/v1/v1/...` hay client tự nối đường dẫn hay không.
- **Vì sao API Key mới không dùng được?** Kiểm tra trạng thái key, credit, nhóm, model ID và định dạng `Authorization: Bearer`.

## Mô hình và chi phí

- **Làm sao biết nhóm dùng được mô hình?** Lọc [Chợ mô hình](https://nexusapi.link/pricing) theo nhóm hoặc gọi `/v1/models` bằng key.
- **Một yêu cầu tốn bao nhiêu?** Xem nhật ký console và [sử dụng và thanh toán](/vi/billing/usage-and-billing).
- **Lỗi có thể bị tính phí không?** Có thể, tùy upstream đã xử lý hay client gửi lại. Hãy đối chiếu Request ID.
- **Có số dư nhưng key bị từ chối?** Kiểm tra cả hạn mức key, ngày hết hạn và nhóm.

## Lỗi API và công cụ

- **400, 401, 429, 500, 502, 503, 504, 524 nghĩa là gì?** Xem [lỗi API thường gặp](/vi/faq/common-errors).
- **Hội thoại dài không tiếp tục được?** Lưu lỗi, mở phiên mới, không gửi lặp nhanh cùng nội dung.
- **Tạo ảnh timeout?** Không gửi lại ngay tác vụ đó; lưu Request ID và xem [hướng dẫn ảnh](/vi/guide/image-generation).
- **`fetch failed` trong Claude Code?** Trước hết thử một tin nhắn ngắn thông thường rồi làm theo [hướng dẫn Claude Code](/vi/tools/claude-code).

## Trước khi liên hệ hỗ trợ

Làm [tự kiểm tra](/vi/faq/self-check), sau đó gửi cùng lúc Request ID, thời gian/múi giờ, client và phiên bản, mô hình, endpoint, toàn bộ lỗi và tình trạng xảy ra ngắt quãng hay liên tục. Không gửi key đầy đủ, mật khẩu hoặc nội dung riêng tư.
