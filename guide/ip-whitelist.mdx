**填了白名单，只有列表中的 IP 能使用这把 Key；留空则不限制 IP。调用仍然需要正确的 Key。**

匹配以平台识别到的来源 IP 为准；代理或网络变化可能影响识别结果，白名单不能代替妥善保管 Key。

适合有固定公网 IP 的电脑或服务器。经常换网络、使用动态 IP 时，先确认出口 IP 是否固定，避免保存后无法调用。

## 1. 先确认该填哪个 IP

填**实际调用 NexusAPI 的公网出口 IP**，不是 NexusAPI 网站的 IP，也不是电脑的局域网 IP。

| 你在哪里使用 Key | 应该填什么 |
| --- | --- |
| 自己电脑上的 Claude Code、Codex 等软件 | 这台电脑访问外网时的公网出口 IP |
| 公司服务器、自建应用或容器 | 服务器实际对外请求的出口 IP；可向运维确认 |
| 通过代理、VPN 或第三方云端工具调用 | 实际转发请求的出口 IP；不一定是你电脑的 IP，先向服务提供方确认 |

不要填 `192.168.x.x`、`10.x.x.x`、`127.0.0.1`，也不要填域名、网址或端口号。

**不知道公网 IP？** 在实际运行软件的电脑或服务器上查询。保持与软件相同的网络和代理设置：

Windows：打开 PowerShell，运行：

```powershell
curl.exe -4 https://api.ipify.org
```

macOS / Linux：打开终端，运行：

```bash
curl -4 https://api.ipify.org
```

返回的一串数字就是该查询请求的公网 IPv4。[ipify](https://www.ipify.org/) 是第三方公网 IP 查询服务，不需要、也不要向它发送 API Key。查询失败时，向公司运维或网络服务商确认。

如果软件单独使用代理、请求从云端发出，或实际走 IPv6，这个 IPv4 查询结果可能不是软件的出口。请先确认实际来源，再填白名单。

## 2. 打开白名单并保存

1. 打开 [API 密钥](https://nexusapi.link/keys)，找到软件正在使用的那把 Key。
2. 点击该行的“编辑”。
3. 展开“高级设置”，找到“IP 白名单（支持 CIDR 表达式）”。
4. 填入实际公网 IP，**每行一个**。
5. 点击“保存更改”。

新建 Key 时也在同一个位置填写。不需要重新复制或更换 Key；修改会影响所有共用这把 Key 的软件和同事，保存前先确认。

## 3. 一个 IP、多个 IP 怎么填

**只允许一个 IP：**

```text
203.0.113.10
```

**允许多个 IP：每个 IP 换一行，不用逗号、分号或空格分隔。**

```text
203.0.113.10
198.51.100.20
```

以上都是演示地址，不能照抄；请替换为你自己的实际公网 IP。不要加 `https://`、`:443` 或 `*`。

## 4. CIDR 表达式怎么配置

### CIDR 是什么

**CIDR 是用一行表示一个 IP 或一整段 IP 的写法：`IP地址/前缀长度`。** 例如 `203.0.113.0/24`。

斜杠后面的数字决定范围大小，**不是端口号，也不是允许的 IP 数量**。`/24` 不代表“允许 24 个 IP”。同为 IPv4 或同为 IPv6 时，这个数字越小，放行范围越大。

只有一台固定出口的电脑或服务器，直接填它的公网 IP 即可，不必改成 CIDR。公司明确给了整个网段，才按提供的 CIDR 填写。

### 常见写法与实际范围

| 写法示例 | 实际允许范围 |
| --- | --- |
| `203.0.113.10` 或 `203.0.113.10/32` | 只允许 `203.0.113.10`，共 1 个 IPv4 地址 |
| `203.0.113.0/28` | 从 `203.0.113.0` 到 `203.0.113.15`，共 16 个 IPv4 地址 |
| `203.0.113.0/24` | 从 `203.0.113.0` 到 `203.0.113.255`，共 256 个 IPv4 地址 |
| `2001:db8::10` 或 `2001:db8::10/128` | 只允许这一个 IPv6 地址 |

这些都是演示地址。不要照抄，也不要把自己的 IP 随手加上 `/24`：这会把一个地址的权限扩大到整个网段。

### 在输入框里怎么填

例如，公司确认允许一个完整网段，另加一台独立服务器，就在“IP 白名单”中分两行填写：

```text
203.0.113.0/24
198.51.100.20/32
```

替换为运维确认的实际网段和服务器 IP，再点击“保存更改”。IP 和 CIDR 可以混填，**每行一条，任意一条匹配即可通过 IP 检查**；其他密钥、模型和额度限制仍然有效。

只有几个不连续的 IP，逐行填写即可。不要填 `203.0.113.*` 或 `203.0.113.10-203.0.113.20`，它们不是支持的 CIDR 写法；也不要只填 `/24`。需要放行一个地址区间但不知道如何转换时，请运维提供准确的 CIDR，不要自行扩大范围。

IPv4 和 IPv6 可以混填；只填 IPv4 不会同时放行 IPv6。需要查询 IPv6 时，可在支持 IPv6 的网络用 `curl -6 https://api6.ipify.org`；Windows 用 `curl.exe`。查不到不代表软件一定走 IPv4。

**不要为了消除报错填写 `0.0.0.0/0` 或 `::/0`。** 它们分别放行所有 IPv4 或 IPv6，失去了限制来源的作用。不确定网段时，先问运维。

## 5. 保存后怎么检查，报错怎么办

回到原软件，发送一次简短请求。能正常返回，说明这次请求通过了 IP 检查；不代表其他来源也已验证。模型测试按正常调用计费。

如果报错包含“您的 IP 不在令牌允许访问的列表中”，或 `403` 的错误原文明确提到 IP 限制，依次检查：

1. 编辑的是不是软件实际使用的那把 Key，是否点了“保存更改”。
2. 多个 IP 是否真的分行，有没有多填网址、端口或错误字符。
3. 是否换了 Wi-Fi、手机热点、代理节点或服务器出口，导致公网 IP 改变。
4. 软件是否实际走 IPv6，或者请求从第三方服务器发出。

仍失败时，把软件名称、发生时间、Key 名称和报错原文发给客服，请协助核对这次请求被识别到的来源 IP。不要发送完整 Key。并非所有 `403` 都是白名单问题，其他情况看[常见报错](/faq/common-errors)。

## 6. 修改或关闭限制

回到同一把 Key 的编辑页：新增地址就另起一行，替换地址就改掉原来那行，再保存。

需要关闭时，清空白名单的**全部内容**，再保存。关闭后不再限制来源 IP，但调用仍需正确的 Key；公司要求限制来源时，先取得管理员确认，不要自行取消。

白名单不能代替保护 Key。Key 已泄露时，按[密钥泄露处理](/guide/api-key)立即停用旧 Key，不要只改白名单。
