---
title: "アクセス方法の概要"
---

NexusAPIは主流のAIクライアントとOpenAIスタイルのインターフェースコールをサポートしています。 異なるツールによって自動的にパスを縫い付けることもあるので、使い方に応じて住所を入力するべきです。

## 始める前の準備

どの方法を使うにせよ、以下の条件が必要です:

1. コンソールでAPIキーを作成します。
2. APIキーグループにターゲットモデルが含まれているか確認してください。
3. モデルプラザから正確なモデルIDをコピーしてください。
4. リクエストはHTTPSアドレスを使って行われます。

## アドレスとプロトコルの比較

| シーン | 住所を記入してください | 主な合意 | 注記 |
| --- | --- | --- | --- |
| OpenAI SDK / 汎用プログラム | `https://nexusapi.link/v1` | チャットの複雑さなど | リクエストパスはSDKやプログラムによって連結されています |
| Codex CLI | `https://nexusapi.link/v1` | 回答 | Codexのチュートリアルにあるプロバイダー設定を使いましょう |
| クロード符号 | `https://nexusapi.link` | 人類的メッセージ | 設定後に複数のアドレスを追加しないでください `/v1` |
| CCスイッチ | 提供者の種類に応じて記入してください | ターゲットツールによります | クロードはコデックスとは異なるアドレスルールを持っています |

上記の表はアクセス方法の選択を助けるために使われています。 インターフェース経路、パラメータ、応答構造は以下のままです。 [APIリファレンスドキュメント](https://nexusapi.apifox.cn/) 標準として。

## なぜ住所が異なるのか

汎用的なOpenAIスタイルのリクエストは通常、以下を使用します:

```text
https://nexusapi.link/v1
```

一部のクライアントはこれを省略する必要があります `/v1` サイト住所は自動的に記入可能です `/chat/completions`、`/responses`、`/messages` その他の道もあります。 正確性については対応するツールのチュートリアルを参照してください。

<Warning>
**同じ道を繰り返さないようにしましょう**

クライアントが自動的にそれを完成させてくれるなら、 `/v1`手動充填後に形成されることがあります `/v1/v1/...` これが404につながりました。 404に遭遇した場合は、まずクライアントの実際のリクエストアドレスを確認してください。
</Warning>
## クライアント設定と一般的なAPIを混同しないでください

CLIツール、エディタプラグイン、カスタムプログラムは異なるプロトコルや設定ファイルを使用する場合があります。 モデル名が同じでも、あるツールの構成全体を別のツールに直接コピーすることはできません。

判断方法:

- Codex CLIの設定:Codexのチュートリアルを読み、関連するResponses設定を使いましょう。
- Claudeコードを構成する:Anthropic環境変数を使ってClaudeCodeのチュートリアルを読んでください。
- 自分でコードを書く:API参照に基づいてリクエストパスとパラメータを選びます。
- 不明な場合は、まずクライアント名と送信されたリクエスト経路を確認してください。

## APIリファレンスドキュメント

インターフェース経路、パラメータ、リクエスト構造、レスポンス構造が完全に揃っています [NexusAPI API 参照](https://nexusapi.apifox.cn/) 真ん中を維持しろ。

ヘルプセンターでは「選び方と使い方」を説明し、 APIリファレンスは「フィールドや構造とは何か」を説明する役割を担っています。

## 設定が成功したことを確認する方法

- クライアントは通常、全内容を返品できます。
- 対応するリクエストはコンソール使用ログに表示されます。
- ログ内のモデル、グループ分け、消費量は期待通りでした。

呼び出しが失敗した場合は、エラーテキストとRequest IDを保存し、その後Enterを入力してください[自己確認](/ja/faq/self-check)。
