このページでは、Claude Code、Codex CLI、Cursor、VS Codeプラグイン、またはカスタムプログラムでAPIを呼び出す際によくあるエラーについて説明します。

## ミスに遭遇したとき、まず何をすべきでしょうか?

以下の順番で扱うことが推奨されます:

1. エラーの原文とリクエストIDを保存してください。
2. 10~30秒待ってからもう一度試します。
3. 同じセッションで失敗し続ける場合は、新しいセッションを作成してから再度試みてください。
4. モデル名、リクエストインターフェース、クライアントバージョンが正しいか確認してください。
5. それでも不合格の場合は、このページの最後にあるチェックリストに従って問題を提出してください。

短期間で高頻度で再挑戦しないでください。頻度制限を引き起こし、繰り返し作業が発生する恐れがあります。

## 500、502、503、504、または524で何が問題なのでしょうか?

これらの状態は通常、サービスが一時的に忙しい、接続中断、または応答タイムアウトを意味し、必ずしもAPIキーやリクエスト自体に問題があるわけではありません。

| ステータスコード | 一般的な意味 | 提案 |
| --- | --- | --- |
| 500 | リクエスト処理に失敗しました | 再検査は後で; リクエストIDが持続したら提出してください |
| 502 | 無効または不完全な回答を受け取ること | 10~30秒待ってからもう一度試してください |
| 503 | このサービスは一時的に利用できません | 繰り返しのリクエストを避けるために後で再度試してください |
| 504 / 524 | 待ち時間が長すぎるとお願いします | 入力を短くするか、後でもう一度試してください |

もし故障が1件だけで、その後自動的に処理が完了する場合、通常は追加の処理は不要です。 同じモデルが連続して故障した場合は、ぜひご連絡ください。

## 429 リクエストが多すぎる

これは現在リクエストが多すぎるか、利用可能な処理能力が一時的な上限に達していることを示しています。

おすすめ:

- 指数関数的なリトリート方法、例えば2秒、5秒、10秒、または20秒待つ方法で再挑戦します。
- 同時実行を減らし、リクエスト頻度を減らしましょう。
- 高同時実行要求に対して複数のプログラムが同じAPIキーを同時に使用することを許可しないでください。
- 低頻度の通話でまだ429が表示されている場合は、リクエストIDをご記入いただきご連絡ください。

## 400の悪いリクエスト

400は通常、リクエスト形式、パラメータ、またはセッション状態が現在のインターフェースと互換性がないことを示します。

順番に確認することをお勧めします:

1. モデル名が正しいか確認してください。
2. リクエストがモデルサポートインターフェースに送られるかどうか。
3. クライアントが最新バージョンかどうか確認してください。
4. 実験パラメータ、ツール呼び出し、セッション継続関数のいずれかが使用されるか。
5. 新しいセッションが作成された後に復元できるかどうか。

修正なしで同じリクエストを繰り返し提出しないでください。 フォーマットの問題は通常、再試行後に自動的に回復しません。

## 思考ブロックにおける無効な署名

このエラーにより、現在のセッションに保存された思考コンテンツは再確認できなくなり、長時間のセッション回復、クライアントの状態変更、または互換性のないセッション内容でよく見られます。

おすすめ:

1. 新しいセッションを作成し、現在のセッションを復元し続けないでください。
2. クライアントを最新バージョンにアップデートしてください。
3. 同じセッションが複数のデバイスで使用されている場合、1台のデバイスでのみ継続可能です。
4. 新しいセッションが表示される場合は、エラー全文とリクエストIDを送信してください。

これらのエラーはモデル出力キャッシュをクリアしても自動的に修正されるわけではありません。最も効果的な処理方法は、通常新しいセッションを作成することです。

## previous_response_idはResponses WebSocket v2でのみサポートされています

これはクライアントが前回の応答を再開しようとしていることを意味しますが、現在の接続方式ではこの再開モードをサポートしていません。

おすすめ:

- 新しいセッションを作成して、もう一度やり直してください。
- クライアントを更新してください。
- 実験セッションの再利用やレスポンス再利用オプションをオフにしてください。
- カスタムプログラムは通常のHTTPリクエストでサポートされていないプログラムの再利用を避けるべきです `previous_response_id`。

## コンテンツブロックが見つかりません

これは通常、クライアントの期待されたコンテンツ断片が完全に受信されていないことを意味します。これは長時間のセッション、ツール呼び出し、応答の中断などが原因かもしれません。

まず新しいセッションを作成し、入力内容を短縮することが推奨されます。 詳細な取り扱い方法をご覧ください [コンテンツブロックが見つかりません](/ja/faq/content-block-not-found)。

## 画像生成は有効になっておらず、モデルもサポートされていません

これは、現在のモデル、アカウントタイプ、またはリクエストインターフェースが要求された機能をサポートしていないことを意味します。

ご確認ください:

- テキストモデルは画像生成インターフェースを呼び出しるべきではありません。
- 画像モデルは文書で指定された画像インターフェースを使用するべきです。
- モデル名の綴りが正しいか確認してください。
- 現在のモデルは画像やツール呼び出し、またはあなたが使っているパラメータをサポートしていますか?

単に再試行するだけでは、対応できない問題は通常解決できません。

## バランスが不十分ですが、コンソールのバランスは正常です

NexusAPIコンソールに十分な残高が確認された場合は、すぐに充電しないでください。 このプロンプトは、依頼されたサービスリソースが一時的に利用できない場合を示す場合もあります。

リクエストIDを保存し、少し待ってから再度お試しください。 もし問題が続く場合は、確認のためにお問い合わせください。

## なぜエラーが最初にログに現れ、その後にタスクが完了したのでしょうか?

システムは部分的な回復可能なエラーが発生した後は自動的に再試行するため、同じリクエストIDがエラーレコードと成功記録の両方を持つことがあります。

最終結果を決定する際は、同じリクエストIDの最後の記録と、クライアントが完全なコンテンツを受け取っているかどうかを参照してください。

## 申請が失敗した場合、請求は発生しますか?

有効なコンテンツが生成されない場合、エラー記録は通常消費ゼロと表示されます。

以下の状況は別途確認する必要があります。

- サービスはコンテンツを生成していますが、クライアントは受付中に切断されます。
- 同じリクエストIDが最初にエラーを引き起こし、その後自動的に完了します。
- クライアントは自分で新しいリクエストを開始します。

重複または失敗の疑いがある場合は、リクエストIDと発生時刻をご記入いただければ、リクエスト記録を検証いたします。 完全なAPIキーを送信しないでください。

## 401 無許可

一般的な原因:

- APIキーの入力が誤っているか、欠落しています `Bearer ` 接頭辞。
- APIキーは削除、無効、または無効になっています。
- リクエストには誤ったアクセスアドレスが使われていました。

APIキーを再度コピーし、リクエストヘッダーを確認してください:

```http
Authorization: Bearer <你的 API Key>
```

## お問い合わせ時に何を提出する必要がありますか?

より早く見つけるために、以下の情報を提供してみてください:

- IDをリクエスト。
- エラー時刻とタイムゾーン。
- 元のテキストまたはスクリーンショットの誤りです。
- 使用されたモデル。
- 使用ツールとバージョン。
- 例えば、リクエストインターフェース `/v1/messages`、`/v1/chat/completions` あるいは `/v1/responses`。
- 問題は、それが断続的に起こるのか、持続的に起こるのか、それとも特定のセッションだけに影響するのかということです。

APIキー、パスワード、プライバシーデータ、または完全なビジネスコンテンツの提出は控えてください。 API Keyは最後の6ビットまで提供できます。
