---
title: "よくある API エラー"
description: "NexusAPI で発生しやすいクライアント、プロトコル、リクエスト、課金のエラーを診断します。"
---

同じエラーを探し、最初の手順を試します。不明ならソフト名、時刻、モデル、グループ、画像をサポートへ。**キー全体を隠し、連続再試行は避けてください。**

## `status_code=500, not implemented`

再試行を繰り返さず、そのソフトでモデルを使えるかサポートに確認します。下の技術説明は自作プログラム向けです。

<Accordion title="技術的な詳細（必要な場合のみ）">

エラーに `status_code=500` と `not implemented` が含まれる場合は、まず選択モデルが現在のエンドポイントのプロトコルをサポートするか確認します。たとえば `/v1/responses` には `supported_endpoint_types` の `openai-response` が必要です。このタイプがない場合は、一時的な上流サービス障害ではなく**プロトコルの非互換**です。

1. 自作アプリは `supported_endpoint_types` に従ってエンドポイントを選びます。`openai` を含む場合は `/v1/chat/completions` を使用します。
2. Claude Code は[Claude Code ガイド](/ja/tools/claude-code)に従い、モデルが `anthropic` に対応することを確認します。
3. 対応するエンドポイントに切り替えてから再度テストしてください。待機やネットワーク変更では解決しません。

サポートには、キーを除いたリクエスト例、モデル名、Request ID を提示します。

</Accordion>

## 400 Bad Request／パラメーター非互換

重要な内容を保存し、新しい会話で短文を一度だけ試します。続くならソフト名・モデル・画像をサポートへ送ります。

<Accordion title="技術的な詳細（必要な場合のみ）">

400 は通常、リクエスト形式、パラメーター、またはセッション状態がエンドポイントの要件に合わないことを示します。

1. モデル ID をモデル広場から正確にコピーします。
2. エンドポイント、モデル、クライアントの組み合わせを[接続方法の概要](/ja/guide/integration-overview)で確認します。
3. 画像、ツール呼び出し、推論、セッション継続のパラメーターがモデルでサポートされるか確認します。
4. 古いクライアントや SDK を更新します。
5. 新しいセッションで短いテキストを送信します。

想定される原因を修正した後、最小リクエストで結果を確認してください。

</Accordion>

## 401 Unauthorized

キー全体をコピーし直してソフトを再起動し、有効・期限内であることを確認します。キー自体はサポートへ送りません。

<Accordion title="技術的な詳細（必要な場合のみ）">

キーがない、誤っている、無効化／期限切れ、または認証ヘッダーの形式が正しくないことが主な原因です。

```http
Authorization: Bearer YOUR_API_KEY
```

コンソールからキーをコピーし直し、リクエスト URL を確認してください。キーの全文はサポートへ送らず、漏えいの疑いがある場合は旧キーを無効化して新しいキーで置き換えます。

</Accordion>

## 403 Forbidden

モデルとグループの権限をサポートに確認します。キーを何度も作り直さないでください。

<Accordion title="技術的な詳細（必要な場合のみ）">

403 はリクエストが拒否されたことを示します。選択グループの権限不足、モデル制限、IP 許可リスト不一致、アカウント状態、または上流サービスモデルサービスの拒否が原因になり得ます。

キーのグループ、モデル制限、IP 許可リストを確認してから短いテキストで試してください。続く場合は Request ID、モデル、時刻、エラー本文を提示します。高頻度の再試行やキーの作り直しではアクセス制限は解消しません。

</Accordion>

## 404 Not Found／リクエストアドレスの誤り

[ソフトの手順](/ja/tools)からアドレスをコピーします。パスを自分で追加しないでください。

<Accordion title="技術的な詳細（必要な場合のみ）">

次を優先して確認します。

- Base URL が `/v1/v1/...` になっていないか。
- クライアントが `/v1` または具体的なパスを自動追加していないか。

URL のルールはツールごとに異なります。[ツールガイド](/ja/tools/)を使用してください。

モデルが使えないことは通常 404 ではありません。キーのグループ外、モデルの一時的な利用不可、利用可能なサービスがない場合は `503` / `no available channel` になることが多いです。

</Accordion>

## 429 Too Many Requests

実行中の処理を待ち、同時タスクを減らして一度試します。続くならサポートへ。

<Accordion title="技術的な詳細（必要な場合のみ）">

429 はプラットフォームのレート制限またはモデルサービスの一時制限で発生します。`Concurrency limit exceeded for user` は通常上流サービスまたはクライアント側の同時実行制限であり、ステータスコードだけでキーの問題とは判断できません。

- 同時実行数を下げ、`Retry-After` があれば優先します。なければランダムジッター付きの指数バックオフを使います。
- 同じキーで複数プログラムが高頻度リトライしないようにします。
- 低頻度でも続く場合は Request ID を提示します。

</Accordion>

## 500、502、503、504、524

エラーを保存し、10～30秒後に一度試します。続くならサポートへ。`not implemented` は最初の項目で確認します。

<Accordion title="技術的な詳細（必要な場合のみ）">

先述の `not implemented` を除き、これらは処理失敗、接続中断、混雑、待機タイムアウトを表すことが多く、キーやプロンプトの誤りとは限りません。

| 状態 | 推奨対応 |
| --- | --- |
| `500` / `502` / `503` | 10～30 秒待ち、一度だけ再試行します。続く場合は Request ID を保存します。 |
| `504` / `524` | 可能ならコンテキスト、ツール呼び出し、出力を短くし、後で試します。 |

同じモデルで長いタスクが連続して失敗する場合は、追加の長いタスクを一度止め、情報を保存してサポートに連絡してください。

</Accordion>

## `no available channel`／現在このモデルに利用可能なサービスがない

グループにモデルがあるか確認します。続くならサポートへ連絡し、このエラーだけで追加チャージやキー作成をしないでください。

<Accordion title="技術的な詳細（必要な場合のみ）">

現在のキーのグループに、そのモデルで利用できるサービスが一時的にない状態です。モデル ID の誤り、グループ未提供、モデルの一時的な利用不可、メンテナンスが考えられます。

後で試すか、モデル広場でそのグループに見える別モデルを使います。続く場合はモデル名、Request ID、時刻を提出してください。このメッセージは再チャージやキーの再作成とは関係ありません。

</Accordion>

## `Concurrency limit exceeded for user`

現在の処理を待ち、同時タスクを減らして再試行します。通常キーの再作成は不要です。

<Accordion title="技術的な詳細（必要な場合のみ）">

アカウントの同時実行リクエスト数が上限です。実行中のリクエストが終わるまで待ち、クライアントの並行数を下げます。このエラーだけでキーを無効化・再作成する必要はありません。

</Accordion>

## 長い会話またはツール呼び出しのエラー

### `Invalid signature in thinking block`

現在のセッションに保存された推論内容を検証できなくなりました。長いセッションの再開、クライアント状態変更、互換性変更で起きることがあります。新しいセッションを作成し、クライアントを更新し、複数端末で同じセッションを続けないでください。

### `previous_response_id is only supported on Responses WebSocket v2`

クライアントが未対応の接続方式で以前の応答を継続しようとしています。新しいセッションを開始し、実験的なセッション継続／応答再利用をオフにするか、クライアントを更新してください。

### `Content block not found`

長い会話、ツール呼び出し、ストリーム中断で、必要な完全なコンテンツ断片をクライアントが受け取れないことがあります。新しいセッションを作り、入力を短くして簡単なテストを行ってください。続く場合は必須でないツール呼び出しを一時的に無効にし、Request ID、発生時刻、モデル、元のエラーをサポートに送ってください。これらの情報をもとに、サービス状態を確認します。

## 残高はあるのにキーが上限不足と表示する

アカウントのクレジット、APIキーの上限、有効期限、キーのグループを確認します。一度の表示でもキーの上限・期限・グループ規則が原因の場合があるため、再チャージの前に確認してください。続く場合は Request ID を提示してください。

## エラーの後、後で自動的に成功するか

エラーが出ても、後でプラットフォームが自動的に完了するとは限りません。通常の呼び出しにプラットフォームレベルの自動リトライ保証はありません。クライアントやアプリが再送すれば、通常は新しい Request ID になります。

対応する Request ID の最終ログと、クライアントが完全な内容を受け取ったかで結果を判断します。二重課金が疑われる場合は関係する Request ID と時刻を提示します。

## サポートに一度に送る情報

```text
ソフト名：
発生時刻：
モデルとグループ：
エラー全文または画像：
Request ID（あれば）：
```

不明な項目は空欄で構いません。キー全体、パスワード、認証コードは送らないでください。
