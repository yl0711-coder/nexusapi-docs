---
title: "自己確認"
---

通話が失敗した場合は、まずこのページをクリックして基本的なチェックを行ってください。 ほとんどの構成や時折の問題は数分で特定できます。

## ステップ1:サイトを保存する

クライアントをクロージングしたり再リクエストする前に、以下を保存してください:

- 原文の完全な誤り
- リクエストID
- 発生時間とタイムゾーン
- 使用モデル
- クライアントと使用されたバージョン
- 例えば、リクエストインターフェース `/v1/responses`

完全なAPIキー、パスワード、プライベートデータ、またはビジネスコンテンツの完全な提出は禁止。

## ステップ2:問題の種類を決める

| 現象 | 優先度チェック |
| --- | --- |
| 401 | APIキー、`Bearer` プレフィックス、リクエストアドレス |
| 404 | ベースURLが重複しているか、欠けているか確認してください `/v1` |
| 400 | モデル、インターフェース、パラメータ、セッション状態 |
| 429 | 並行性とリクエスト頻度 |
| 500 / 502 / 503 | 10~30秒待ってからもう一度試してください |
| 504 / 524 | リクエスト内容、待ち時間、サービス状況 |
| 不十分な残高 | コンソール残高、キー数、そしてグルーピング |

具体的な意味については、以下を参照してください [APIコールFAQ](/ja/faq/common-errors)。

## ステップ3:最低限の検証を行う

1. コンソールのバランスとAPIキーが正常に動作しているか確認してください。
2. モデルの四角からモデルIDを再コピーしてください。
3. 新しいセッションを作成し、短いテキストを送信してください。
4. 再試行は一度だけで、新しいリクエストIDを記録してください。
5. コンソール使用履歴に対応するリクエストが表示されているか確認してください。

新しいセッションが成功した場合、問題は通常元のセッション状態またはリクエストの内容に関連しています。 最小限のリクエストでも失敗し続ける場合は、質問を提出してください。
