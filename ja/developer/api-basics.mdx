このページでは、すべてのモデル呼び出しに共通する基本ルールと、**選ぶべきプロトコルおよび安全な開始方法**を説明します。

<Info>
**先に対応状況を確認してください**

利用可能なモデルは APIキーのグループ、モデル制限、リアルタイムの状態によって変わります。モデル広場の全体一覧は、特定のキーで必ず呼び出せることを保証するものではありません。
</Info>

## 必要な 3 つの値

| 値 | 取得場所 | 用途 |
| --- | --- | --- |
| Base URL | このページ | SDK / クライアントのリクエスト送信先 |
| APIキー | コンソール → APIキー | 呼び出し元と利用可能グループの識別 |
| モデル ID | モデル広場または `/v1/models` | 呼び出すモデルの指定 |

標準的な OpenAI 形式クライアントでは、次を使用します。

```text
https://nexusapi.link/v1
```

手動 HTTP リクエストではキーを `Authorization` に入れます。

```http
Authorization: Bearer YOUR_API_KEY
```

キーの全文をフロントエンド、スクリーンショット、チャット履歴、Git リポジトリに入れないでください。URL の指定方法はクライアントにより異なります。Claude Code は `/v1` なし、Codex CLI はプロバイダー設定を使用します。該当する[クライアントツールのガイド](/ja/tools/index)に従ってください。

## このキーで見えるモデルを一覧する

```bash
curl 'https://nexusapi.link/v1/models' \
  -H 'Authorization: Bearer YOUR_API_KEY'
```

`data[].id` からモデル ID をコピーします。これは**そのキーで現在見えている**モデルの一覧であり、プラットフォーム全体のカタログではありません。`data[].supported_endpoint_types` には、そのモデルで現在利用可能なリクエストプロトコルが列挙されます。記載された種類に対応するパスだけを使用します。`openai` は Chat Completions、`anthropic` は Messages、`openai-response` は Responses。複数の種類がある場合は、クライアントに合うものを選んでください。

## 正しいプロトコルを選ぶ

| 目的 | パス | 利用場面 |
| --- | --- | --- |
| OpenAI 互換のテキスト、チャット、ストリーミング | `POST /v1/chat/completions` | `supported_endpoint_types` に `openai` を含むモデル。多くの自作アプリ、OpenAI SDK、汎用クライアント向け |
| ネイティブ Anthropic / Claude Code | `POST /v1/messages` | `supported_endpoint_types` に `anthropic` を含むモデル |
| Codex プロバイダー | `POST /v1/responses` | [Codex CLI ガイド](/ja/tools/codex-cli)に従い、`supported_endpoint_types` に `openai-response` を含むモデルの場合のみ |

同じモデル名でも、すべてのリクエスト形式を受け付けるとは限りません。[API とモデル対応マトリクス](/ja/developer/capability-matrix)で確認してから、次を読んでください。

- [Chat Completions](/ja/developer/openai-compatible)
- [Anthropic Messages](/ja/developer/anthropic-messages)
- [Responses / Codex](/ja/developer/responses)

## 最小検証と再試行の原則

1. まずモデル一覧を取得し、短いテキストを 1 回送ります。
2. モデル ID、キーのグループ、パスを確認してからオプション、ストリーミング、バッチを追加します。
3. 失敗時はエラー文、時刻、Request ID を保存し、結果未確認のリクエストを高頻度で再送しないでください。

`401` はまずキー、`404` は `/v1` の不足または重複、`400` はモデル、プロトコル、フィールドを確認します。詳しくは[セルフチェック](/ja/faq/self-check)を参照してください。
