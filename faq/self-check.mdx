遇到调用失败时，先按本页完成基础检查。多数配置或偶发问题可以在几分钟内确定范围。

## 第一步：保存现场

在关闭客户端或重新请求前，先保存：

- 完整错误原文
- Request ID
- 发生时间和时区
- 使用的模型
- 使用的客户端及版本
- 请求接口，例如 `/v1/responses`

不要提交完整 API Key、密码、隐私数据或完整业务内容。

## 第二步：判断问题类型

| 现象 | 优先检查 |
| --- | --- |
| 401 | API Key、`Bearer` 前缀、请求地址 |
| 403 | Key 分组、模型限制、IP 白名单、账号状态或上游拒绝 |
| 404 | Base URL、接口路径是否重复、缺少或误拼 `/v1` |
| 400 | 模型、接口、参数和会话状态 |
| 429 | 并发和请求频率 |
| 500 / 502 / 503 | 等待 10～30 秒后重试一次 |
| 504 / 524 | 请求内容、等待时间和服务状态 |
| `500, not implemented` | 不要重试；检查是否用 `/v1/responses` 调用了 Claude 模型 |
| `no available channel` / 503 | 模型 ID、Key 分组、该模型是否有启用渠道 |
| 图片生成超时 | 不要重复提交同一任务，保存 Request ID 和发生时间 |
| 余额不足 | 控制台余额、Key 额度和分组 |

具体含义见 [API 调用常见问题](/faq/common-errors)。

## 第三步：做一次最小验证

1. 确认控制台余额和 API Key 状态正常。
2. 从模型广场重新复制模型 ID。
3. 新建会话，发送一条简短文本。
4. 只重试一次，并记录新的 Request ID。
5. 查看控制台使用日志是否出现对应请求。

如果新会话成功，问题通常与原会话状态或请求内容有关；如果最小请求也持续失败，请提交问题。

## 联系支持时提供

请一次性提供：

```text
发生时间（含时区）：
Request ID：
客户端及版本：
模型：
请求接口：
错误原文：
偶发还是持续发生：
是否已用新会话验证：
```

信息越完整，定位速度越快。API Key 最多提供末 6 位。
